# 分けて回す・続ける・合わせる

## 表と shard
表は `src/table.mjs` の `buildJobs` が作る（CPU A・CPU B、`--swap`、デッキ、シード）。順番は固定で、機械にも時刻にも依らない。
`--shard i/n`（i は 1〜n）は、表の k 番目（0 始まり）の試合を `(k mod n) + 1` 番目の shard に入れる。
- どの試合もちょうど 1 つの shard に入る（重ならない・漏れない）。
- 試合の長さはデッキの組で偏るが、隣り合う試合は別の shard に入るので、shard ごとの重さは揃う。
- shard の中身は、表の定義（CPU・デッキ・シード・`--swap`）と `n` だけで決まる。どの機械でも同じ。
- 試合の結果は、試合の名前（`<A>.<B>/<デッキA>/<デッキB>/<シード>`、ゲームに渡す match id でもある）とシードで決まる。回す順番・並列数・機械に依らない。

## 続きから回す
止まったら、同じコマンドをもう一度。`<out>/raw.jsonl` にある試合は飛ばす。
- 途中で強制終了されて半端な 1 行が残っていても、その行は無視して、改行を足してから追記する。
- 子プロセスが試合の途中で落ちたら、その試合を 1 回だけ別のプロセスでやり直す。それでも落ちたら `worker_crash` の異常として記録して先へ進む。
- 続きは、前と同じ環境でなければ回さない（下の `env.json`）。

## 環境の記録（`<out>/env.json`）
- `key`（同じでなければ混ぜない）: node の版、ゲームのコミット（と、チェックアウトが綺麗か）、表に出る CPU 全部の版（ファイルのハッシュ。改行コードは無視）、試合を回すこの道具のコード（`src/play.mjs` `src/worker.mjs` `cpus/index.mjs` のハッシュ）、打ち切りの上限。
- `info`（記録するだけ）: 機械、OS、ゲームの件名。
`env.json` は shard ごと・結果ごとに作られる。

## 合わせる
```
node src/merge.mjs --out merged shards/1 shards/2 shards/3 shards/4
```
- 表か環境（`key`）が違う結果が混ざっていたら、何も書かずに止まる（終了コード 2）。
- `merged/raw.jsonl` に、各試合を 1 回ずつ、表の順で書く。`config.json`・`env.json`・`merge-report.md` / `.json` も書く。
- `merge-report` に出るもの: 足りない試合（どの shard のものか）、重なった試合（結果が同じなら 1 つにまとめる）、重なって結果が違う試合（あってはならない。先に見つけた方を残して報告）、表にない試合、別の shard の結果に入っていた試合、読めない行、結果の出た OS の一覧。
- 終了コード: 足りない・食い違い・表にない・別 shard があれば 1（`--allow-partial` で足りないだけなら 0）。
- 合わせた結果は `src/report.mjs` でそのまま集計できる。別々の機械の結果を合わせたときの時間の表は意味がない（集計にもそう書かれる）。

## 一致の確かめ方
```
node src/compare.mjs <結果A> <結果B>
```
共通の試合について、手順のハッシュ・結果・ターン数・先手の席が一致するかを見る。
- shard を合わせた結果と、表を 1 回で通した結果の一致
- 別の機械・別の OS（Windows と Linux）の一致
`src/determinism.mjs` は、同じ表の一部を並列数・順番・プロセスを変えて 2 回回して比べる。

## GitHub Actions
`.github/workflows/bench.yml` は下書き（手動実行のみ）。shard ごとに回して成果物にし、最後に合わせて集計する。まだ使っていない。
